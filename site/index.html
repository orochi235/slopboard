slopboard

A wall for AI-generated renders, filling a side monitor. Images arrive from agents, live for a while, then disappear unless rescued.

Open the demo wall Source on GitHub

The demo runs on a fixed set of real renders and a fake daemon, so nothing arrives from anywhere. Pictures still age out and the controls still work.

Why it forgets

Most software defaults to hoarding: every generated image lands in a folder that becomes archaeological sediment. Roughly nine in ten of these are slop, and the name is there to stop it drifting into an asset manager. So the wall is ephemeral by default, and permanence is earned by an act of attention — right-click a card and pin it, and it stops decaying.

It replaces telling agents to open renders in Preview, which steals focus every time for a picture that usually was not worth turning to look at.

Putting something on it

Writing the file is the whole protocol. There is nothing to start or connect to.

slop render.png

The zone is the directory name of the repository you ran in, so a project is on the wall the first time it renders and nothing has to be bound. A zone is one pile, which is what makes “which projects are producing” answerable from across the room. Pipe a generator straight in, or pass --ttl, a caption, or a question the card waits on an answer to.

How it is put together

A Node daemon watches ~/slop/inbox/, downscales what lands, and pushes it over a WebSocket. The client is React and three.js: one diagonal pile per zone, drawn in WebGL, read head-on at wall distance and zoomed into for the detail.

Layout comes from windease, which places the zones; the right-click menu is a delamin8r parallax window; the menu bar app is generated by perch. The design doc in the repo says what is decided and what is still open.
