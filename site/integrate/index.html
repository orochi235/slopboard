Putting your repos on it

Run the wall, wire it to the agents on your machine once, and every repo you work in is on it the first time something renders.

Back to the front Source on GitHub

Run the wall

macOS, Node 22 or newer. The daemon and the client come up together.

git clone https://github.com/orochi235/slopboard
cd slopboard
npm install
npm run dev

The client is at localhost:5183 and the daemon at localhost:8787, watching ~/slop/inbox/. Put it on the monitor you do not type on.

Wire it to your agents

Once per machine, and again after you change anything here — it is idempotent.

bin/wire        # --dry says what it would change
                # --off takes it all back out

It puts three things where an agent will meet them:

  • The skill, symlinked into every ~/.claude*/skills/. It tells an agent how to send, how to diagnose a render that never arrived, and how to except a repo.
  • The wall-nudge hook, a PostToolUse entry in each settings.json. It fires when an agent reads or creates an image that never reached the wall and hands the model a one-line correction, which is what stops renders dying in a scratch directory.
  • slop on PATH, symlinked into ~/.local/bin. Without it an agent that half-remembers the rule types slop chart.png, gets command not found, and goes back to reporting a file path.

A session that was already running keeps the hooks it started with, so a live one is not evidence that wiring failed. wire also prints a rule for your CLAUDE.md and leaves you to paste it: that file is hand-written prose, and a tool that rewrites preferences fights their author.

There is no per-repo setup

A zone is one pile on the wall, and the zone is the directory name of the repository you ran in. Nothing registers a project: the first send creates its zone, and bin/slop records which directory the renders came from so the daemon can read that project’s .hued file and paint the pile in its color. 

slop render.png              # the zone is this repo
slop --zone icons sheet.png  # or say where it goes
some-generator | slop        # a pipe is a send too

What a send can carry

Every flag is optional, and the file alone is the whole protocol. These are the ones worth knowing on the first day: 

slop --ttl 5m draft.png           # how long it lives
slop --caption "after the fix" a.png
slop --attention soon broken.png  # or look, urgent, problem
slop --ask "which crop reads better?" \
     --choice left --choice right crop.png

--ask puts the question on the card, waits, and prints the answer, so an agent can stop and ask you something about a picture instead of guessing. Runs of pictures share one card with --run; video, self-contained HTML pages and .glb/.stl meshes land as cards whose lightbox plays, runs or orbits the real thing.

Excepting a repo

Some work should not go on a wall someone else can see. The skill covers putting one repo back to opening images locally, or sending it to a zone that is not its directory name, without changing anything for the others. Ask for it in those words — “stop sending renders to the wall here” — and the agent has the instructions.
